# 짚불 메인 앱

실제 GLB와 원본 영상을 함께 검토하는 로컬 데스크톱 웹 앱이다. 분석 화면, 이동 가능한 워크스루, 영상–GLB 수동 연결, 전체/집중 관계도와 Astra 분석을 제공한다. 기획서의 확장 하네스 전체를 구현한 상태는 아니다.

## 실행

Node.js 22 이상과 `ffmpeg`, `ffprobe`가 필요하다. 서버는 모노레포 루트의 `.env`에서 `OPENAI_API_KEY`를 읽는다. 키는 각 개발자가 별도로 준비하며 프런트엔드 환경변수에 넣지 않는다.

```sh
cd zipbul
npm ci
npm run dev
```

브라우저: http://127.0.0.1:3000 · 로컬 API: http://127.0.0.1:3001

프로덕션 빌드는 `npm run build`, 실행은 개발 서버를 종료한 뒤 `npm start`를 사용한다. 두 서버 모두 로컬 머신에서만 수신한다. 공개 배포·인증·팀 간 저장소 동기화는 포함하지 않는다.

## 입력

화면의 **현장 추가**에서 내장형 GLB와 MP4/MOV를 선택한다. `frames.jsonl`은 선택 사항이다. 자세 정보가 없으면 자동 위치 후보 없이 수동 연결을 사용한다. 외부 파일을 참조하는 GLB, 삼각형 이외의 메시, Draco 등 별도 디코더가 필요한 입력은 내보내기 설정을 바꿔야 할 수 있다.

Zipscan 전체 세션을 사용할 때는 다음 명령을 실행한다.

```sh
npm run import -- "/path/to/zipscan-session" "/path/to/textured.glb"
```

세션에는 `manifest.json`, `frames.jsonl`, `video.mp4`가 필요하다. `depth-index.jsonl`, `depth.bin`, `confidence.bin`이 있으면 깊이 기반 위치 후보를 계산한다. 메타데이터는 `video_status`, 실제 초 단위 `video_pts`, `frame_id`, `image_width/height`, 행 배열 `camera_transform`, `intrinsics`를 사용한다. 자세가 없으면 두 행렬은 빈 배열이다. ARKit 미터 좌표, +Y 위, 카메라 -Z 전방을 기준으로 한다.

CLI 가져오기는 원본 경로를 등록하므로 원본 파일을 옮기거나 삭제하면 안 된다. 브라우저 업로드는 원본을 `data/imports/`에 보관한다. `data/`는 Git에 포함되지 않으며 팀원은 입력을 별도로 받아야 한다.

## 시연 순서

1. 분석 화면에서 WASD/방향키로 이동하고 Q/E로 하강·상승한다. Shift는 빠른 이동, 휠·+/− 키·상단 버튼은 확대/축소다. 점검 항목을 선택하면 영상의 표시 영역을 확인할 수 있고, 원본 영상 재생은 해당 PTS로 이동한다.
2. **수동 위치 연결**을 누르고 원본 GLB 면을 클릭한다. 표시된 점을 확인한 후 **이 위치로 연결**로 저장한다. 이후 항목 선택은 대상 가까이 이동한다.
3. **전체 관계도**에서 전체 노드를 펼친 뒤 **집중 보기**와 근거 노드를 선택한다.
4. **워크스루 → 탐사 시작**으로 이동한다. WASD/방향키 이동, 마우스 시점, Shift 빠른 이동, E 가까운 연결 항목, Esc 멈춤, F 전체 화면을 사용한다. 포인터 잠금을 사용할 수 없는 환경에서는 왼쪽 드래그로 시점을 조작한다.
5. **원본 비교**로 같은 카메라에서 재구성 장면과 원본을 비교한다. 전달받은 현장의 강의실·복도·라운지·카페를 영상/GLB/깊이를 참고해 재구성했다. 책상·의자·연단·수납장·카트·식물·조명 등은 개별 3D 형상이며 일부 표면에 원본 영상 텍스처를 사용한다. 배치와 치수는 추정이다.
6. 바닥 보정은 원본 면을 선택해 작은 구역에 추가한다. 이동 연결은 직선 후보를 캡슐 충돌·접지로 검증하며 장애물이 있으면 안내선을 내지 않는다. 보정이 포함된 구간은 시뮬레이션으로 표시한다.

깊이 기반 위치 후보는 사용자 확인 전 자동 포커스하지 않는다. AI 후보와 사용자 위치 확인·검토 기록은 별도로 보존한다. 자동 테스트의 위치 확인·검토 기록은 별도 복제 현장에서만 생성하고 제거했다.

## 데이터·실행 구조

- Next.js/React/TypeScript, Three.js, Rapier, React Flow + Dagre.
- Express 로컬 API, OpenAI SDK, Zod, FFmpeg, glTF Transform.
- `gpt-6-astra`만 사용한다. 15초 간격 표본을 최대 6장씩 background Responses로 분석한다. Decisions 호출은 없다.
- 작업/응답 ID·상태·사용량·결과 revision을 JSON으로 보관한다. 실행 중인 분석은 서버 재시작 후 저장된 응답 ID부터 재개한다. 취소 후 늦은 결과는 공개하지 않는다.
- `manual.json`은 사용자 위치와 검토 기록을 별도로 보존한다. GLB revision이 바뀐 연결은 재검토 상태가 된다.
- `navigation.json`은 구간별 원본 지지/보정 ID와 브라우저 Rapier 검증 결과를 보관한다. 보정·충돌 구현 revision 변경 시 기존 결과는 무효다. JSON 내보내기에 포함된다.
- `data/scenes/<id>/scene.json`은 원본 경로, `render.glb`는 형상을 보존한 표시용 텍스처 최적화본, `collision.glb`는 간소화한 충돌 메시다. 원본 GLB 다운로드 경로도 유지한다.

## 검증과 현재 한계

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

`npm test`는 로컬 저장·데이터 계약과 합성 데이터 기반 Sites API를 함께 검사하며 원본 촬영 파일이나 실제 모델 호출이 필요하지 않다. `node:sqlite`를 사용할 수 있는 Node.js 22.13 이상이 필요하다. 브라우저 검증은 실행 중인 서버와 전달받은 실제 세션을 필요로 하며, 현재 Mac의 headed Chromium/Metal을 사용한다. 테스트가 만드는 복제·합성 현장은 종료 시 제거한다. 결과와 캡처는 `output/`에 남는다.

2026-10-09 로컬 확인: 실제 277.89초 영상의 19개 표본에서 Astra 분석 4개, 실제 근거 대화, 수동 연결/검토/새로고침 보존, 전체 17개 노드/집중 4개 노드, 영상 Range 재생, 메타데이터 없는 업로드, 이동/접지/벽 충돌, 보정 경로 기록/무효화를 확인했다. 단위 테스트 6개와 타입 검사·빌드가 통과했다. 실제 M4 Pro/Metal의 보완 장면 측정은 약 54–74 FPS였으며 보장 수치는 아니다. Headless SwiftShader의 1–2 FPS는 소프트웨어 렌더링 결과다.

추가 구현: 분석의 자유 이동·확대/축소, 전달받은 현장 전체 구역의 게임용 장면과 충돌 형상을 반영했다. 재구성 지지면을 지나는 이동은 시뮬레이션으로 표시한다. 이 후속 변경은 요청에 따라 기본 동작과 화면 위주로 확인했으며 전체 검증 묶음을 다시 실행하지 않았다.

원본에는 누락 면과 거친 가구·벽이 있어 재구성 장면은 추정 복원이며 실제 공간과 100% 일치하지 않는다. 현장별 재구성은 현재 전달받은 GLB revision에 적용된다. 모델이 추가 crop/프레임을 선택하는 다단계 하네스, 그래프 검색·필터·자동 묶기, 우회 경로 탐색은 남아 있다. 19개 표본 분석은 전체 영상의 위험 누락 검증이나 현장 안전 판정을 뜻하지 않는다. 다른 팀원 머신·공개 배포는 검증하지 않았다.

## 공간 선택과 분석 이력

상단 **공간 선택** 드롭다운에서 현장을 전환한다. 선택은 URL의 `scene` 및 브라우저에 보관되며, 현장별 GLB·영상·위험 후보·사용자 기록을 따로 읽는다. 전환 시 열린 점검, 카메라, 대화와 경로를 초기화한다.

- **현장 01 · 센터필드 18층**: 기존 11:57 세션. 영상 4분 38초, 표본 19개. 영상 기반 개별 가구 재구성이 적용된 공간이다.
- **현장 02 · 센터필드 1층**: 별도 장소의 13:49 세션 `33a46c91-0ba7-44f8-99dc-bfe3588c539a`. 대응 ZIP의 영상 10분, 표본 41개와 새 GLB를 사용한다. 원본 GLB 368.6 MiB, 표시용 159.3 MiB, 충돌용 8.2 MiB. 자전거 보관소·전동 자전거 구역·복도·외부 계단에 전용 Three.js 재구성 176개 구성 자산을 적용했다. 자전거/거치대의 세부 형상, 재질, 조명, 접지·충돌을 포함하고 원본과 같은 시점에서 비교할 수 있다. 사용자 요청으로 Astra 표본 분석을 실행해 16개 점검 후보를 저장했다. 등록만으로 AI 분석을 자동 실행하지 않는다.

**새 위험 분석**에서 전체 영상 표본 또는 현재 프레임을 골라 실행한다. **분석 이력**은 실행 시각·진행 상태와 당시 저장된 AI 결과를 읽기 전용으로 보여준다. 과거 AI 결과와 현재 수동 검토 상태를 구분하며 현재 점검으로 다시 연결할 수 있다.

두 번째 세션 ZIP은 `data/imports/session-33a46c91-0ba7-44f8-99dc-bfe3588c539a/`에 추출했다. Downloads의 11:57 세션과 연결하지 않았다. 두 번째 원본 GLB는 Downloads 경로를 참조하므로 옮기지 않는다.

다음 경량화·배포 작업의 입력 목록은 `output/deployment-asset-inventory.json`에 기록했다. 현재 표시용 GLB는 텍스처만 최적화하며 면 순서를 보존한다. 후속 메시 단순화나 압축 시에는 원본 표면 ID 및 수동 연결의 유효성을 확인해야 한다. 이번 추가 현장과 분석 이력 UI는 로컬 구현이며, Sites에 반영하려면 새 현장 자산 전송과 클라우드의 `GET /api/scenes/:id/analyses/:run` 이력 응답 대응이 필요하다.

### 업로드와 배포 전 확인 (2026-10-09)

- 현장 01은 센터필드 18층, 현장 02는 센터필드 1층이다. 새 업로드는 현장 이름을 입력하며, 이름을 비우면 GLB 파일명을 사용한다. 기존 현장을 다시 가져올 때는 이름을 보존한다.
- 새 현장은 GLB와 MP4/MOV를 **함께** 제출한다. 영상만 또는 GLB만의 등록/분석은 현재 지원하지 않는다. `frames.jsonl`은 선택 사항이며, 없으면 위치 미확인/수동 연결로 분석한다. 등록 후 `새 위험 분석`에서 분석 범위를 선택한다.
- 브라우저는 같은 도메인의 `/api/uploads`로 4 MiB씩 분할 전송한다. 각 파일 최대 1.5 GiB, 처리 상태를 표시한다. 3001 포트에 직접 접속하는 업로드 경로를 제거했다. Node 서버에서 FFmpeg 전처리 후 별도 현장으로 저장한다.
- 실제 스캔 파생 GLB(424,862 triangles)와 원본 영상 2초를 4개 조각으로 전송해 새 현장 생성, 사용자 이름 보존, 카메라 정보 없는 입력, 실제 Astra 1프레임 분석 완료(후보 2개), 분석 이력 조회까지 확인했다. 테스트 현장만 정리했고 기존 2개 현장 기록은 보존했다. 결과: `output/import-readiness.json`. 이는 대표 업로드 확인이며 최대 용량 부하 검증은 아니다.
- 근거 박스는 제목줄 드래그/방향키로 이동하며 화면 안에 유지된다. X는 박스만 숨기고 현재 카메라와 선택/영상 근거를 보존한다. 같은 항목을 다시 선택하면 박스가 열린다.
- **서버형 배포**에는 Next + Node API, FFmpeg/ffprobe, 영구 `data/` 저장소가 필요하다. 서버 환경 `ZIPBUL_ALLOWED_ORIGINS`에 실제 HTTPS 앱 origin을 쉼표로 지정한다. reverse proxy 또는 터널은 Next 포트로 연결한다.
- **기존 Sites 배포**는 `sites/ImportScene.tsx`의 제한 화면과 별도 클라우드 어댑터를 사용하므로 신규 원본 업로드가 지원되지 않는다. 위 로컬 확인을 Sites 배포 검증으로 간주하면 안 된다. 이 변경은 아직 배포하지 않았다.
